# 1.6.5 Windows diagnostic: recycled message slot retention

Base: c940ff6a6efe7c7d774cee0d5e55cd541f8ccaf1 (TDZFix). Signal core, SQL tables/migrations and haituo-scroll.js are unchanged.

The existing slotFor already checked connectivity, but did not help if process was never invoked after a WhatsApp removal/reuse path. Main-world creation hooks now also cover removeChild/remove. Cloned light-DOM slot shells without a closed shadow are discarded so each message retains exactly one live host. A same-key host found detached or under the wrong parent is appended back synchronously, preserving its closed shadow content. Source changes discard the old keyed state. A rendering guard prevents our own DOM work recursively processing the same message.

An isolated-preload MutationObserver independently handles childList, characterData and message identity/class changes, without relying solely on main-world DOM events. Affected messages are processed in the mutation callback. Visible [data-id] nodes are reconciled on scroll immediately, on a scheduled animation frame, and once after a 100ms wheel/scroll/mutation debounce; scrollend reconciles immediately as well. No interval polling, scrollTop assignments, remote request retries or database schema changes are added. Observers/listeners/frame/timer are disposed with the controller.

Synchronous creation/insertion/removal hooks remain the primary rendering path: a memory cache hit is rendered before that DOM call returns. Scroll-end rehydration is a recovery path, not the completion criterion. Unknown disk state retains the existing protected original/loading behavior until lookup resolves. Cached recovery does not issue another translation request. The slot remains a closed ShadowRoot to avoid copying translated text into native message text.

Both the original message element and attached slot carry data-translation-cache-hit="true" only while rendering a hit. The marker is removed for other states/source changes. Do not add the two marker counts together as two messages.

Local validation: 387 unit tests and 22 DOM/Signal component tests pass. Newly added regression cases fail on the old code. Tests cover synchronous host removal/re-attachment, raw native deletion + scroll, repeated long-message recycling, source edits, clean native copying and two independent webview caches. The native synthetic Chromium fixture adds 12 alternating rapid-scroll cycles using 40 reused rows (480 explicit slot removals, plus raw native removals), including a long English source, with cached hit markers and no new lookup/translation assertions. It retains per-frame sampling at 1x and CPU 6x.

Target-OS native results must be taken from CI; a synthetic native fixture is not a real linked-account test. Real WhatsApp rapid-scroll behavior remains UNTESTED until the user repeats their cc69/149 account checks with the new binary. No merge, release or R2 publication. Windows installer/source are uploaded after the critical native settings/resident suite, before unrelated dependency/network tail checks.
